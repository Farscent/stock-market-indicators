# Stock Market Indicators with Python

An introductory capital-market analysis project using pandas rolling windows. It calculates moving averages, daily returns, volatility, drawdown, and historical BUY/SELL crossover events.

**Research question:** How can we describe a price trend and detect a moving-average crossover without using future prices?

## Example results

![Moving averages, crossover events, and drawdown on the simulated DEMO series](docs/overview.png)

| Measure | Result |
|---|---:|
| Observations | 260 |
| Historical BUY / SELL events | 2 / 2 |
| Closing-price return | 13.20% |
| Annualized daily volatility | 6.99% |
| Maximum drawdown | -12.36% |

These are descriptive results for the simulated input series. The 13.20% price change is **not a crossover strategy return**. [Read the generated example report](docs/example-report.md).

## What this project teaches

- The difference between price levels and percentage returns.
- Trailing rolling windows and the need for a warm-up period.
- Boolean conditions for detecting a change rather than labeling every row.
- Basic risk measures and the limits of technical indicators.
- Reading, validating, sorting, and plotting a daily price series.

## Data

[data/demo_prices.csv](data/demo_prices.csv) contains **260 simulated weekday observations** for a fictional asset called DEMO. It is generated by [make_demo_data.py](make_demo_data.py) using a trend plus smooth cycles. It is not downloaded market data and does not represent an actual company.

| Column | Meaning |
|---|---|
| date | Observation date in YYYY-MM-DD format |
| close | Positive closing price, in arbitrary price units |
| volume | Simulated number of units traded; included for a volume-chart exercise |

Weekdays are used for convenience; actual exchange holidays are not modeled. The synthetic trends make crossovers easy to see and do not establish that a trading rule works.

## The calculations

~~~text
daily return = today's close / previous close − 1
n-observation SMA = mean of the latest n closing prices
cumulative price return = today's close / first close − 1
drawdown = today's close / highest close so far − 1
annualized volatility = sample standard deviation of daily returns × √252
~~~

A move from 100 to 105 is a 5% daily return. A fall from a previous high of 120 to 90 is a −25% drawdown. Maximum drawdown is the most negative drawdown in the observed period.

The 252 factor is a conventional approximation for daily trading observations. It is not appropriate for weekly data or every market. The rolling volatility column needs 20 valid daily returns, so its first value occurs after 21 prices.

## BUY and SELL events

The default windows are 20 and 50 observations. Both are trailing windows, including the current close.

| Event | Rule |
|---|---|
| BUY | Fast SMA was at or below the slow SMA, then becomes strictly above it. |
| SELL | Fast SMA was at or above the slow SMA, then becomes strictly below it. |
| NONE | No new crossover, including the warm-up period. |

Two consecutive valid SMA comparisons are required. The first valid pair of averages does not automatically create a BUY. A trend can remain ABOVE for several days while the signal is NONE.

These labels mark historical technical events. They are **not recommendations, executed trades, or proof of profitability**. Moving averages lag prices and may produce repeated false signals in a sideways market.

A signal at day t is known only after day t's closing price is available. A later backtest would need an explicit next-session execution rule, fees, slippage, position sizing, and an untouched evaluation period. This project does not report strategy returns.

## Outputs

| Output | Contents |
|---|---|
| outputs/indicators.csv | All prices, averages, returns, risk measures, and events |
| outputs/crossovers.csv | Only dates with a new BUY or SELL event |
| outputs/summary.json | Period, price return, volatility, drawdown, and event counts |
| outputs/report.md | Plain-language summary |
| outputs/market_overview.png | Price/average chart with markers and a drawdown chart |

The reported cumulative price return describes the input series. It excludes cash dividends and trading costs and is not the return of a crossover strategy.

## Use your own data

Export a permitted daily price history for **one asset**, with at least 51 rows for the default settings:

~~~csv
date,close
2025-01-02,100.00
2025-01-03,101.50
~~~

The two rows above illustrate the schema only. Save a full history and run:

~~~bash
python indicators.py --input data/my_prices.csv --output outputs/my_asset
~~~

Dates are sorted; duplicate dates, missing prices, nonpositive prices, and infinite prices are rejected. Missing prices are not forward-filled. Extra columns are retained but not required.

Use a consistent price basis and document its source, download date, currency, frequency, and split/dividend adjustment method. Unadjusted corporate actions can create artificial jumps. A column called close is not automatically adjusted.

## Study and extension

Start with [walkthrough.ipynb](walkthrough.ipynb) and [indicators.py](indicators.py).

1. Calculate a three-observation moving average by hand.
2. Compare 10/30 and 20/50 windows without assuming more signals are better.
3. Add a volume chart.
4. Explain why a high-priced stock is not necessarily a large company: market capitalization also depends on shares outstanding.
5. Extend the indicator study into a clearly specified paper backtest with realistic timing and costs.

The tests include a small hand-calculated crossover example and a check that modifying future prices cannot change past indicator values.
